# example_project_repo

This repository(repo) should be the template for projects going forward. Code availability and replicability are very important, and we as scientists should strive to make our work clean, readable, and accessible for better communication and collaboration.

Every repo should include a README.txt or README.md that details a short overview of the project. Some additional things that you could include are:

- a citation (if it is published)
- collaborators
- links to other tools or repositories that were used

Outside of the README, there should be separate folders for each analysis/ pipeline that was conducted within the project. **This can vary.** For fieldwork or wetlab procedures, I would recommend a write up in a text document, and any supporting materials necessary for that method. 

I would also include a CSV or XLSX that includes isolate naming conventions and any other important metadata relevant to the sample. **THIS IS IMPORTANT**. In computational biology and bioinformatics, it is important to keep a paper trail that allows 
data to be recovered or recognized in the event that file names change either during analysis or through user error (both have happened to me).


For code, I highly recommend clearly naming your scripts and commenting them out, and maintaining some form of chronological order. In some instances, you may even need to have certain analyses conducted upstream rather than downstream, and your folder naming conventions and order should reflect that. 

For the rest of this repo, you can explore it as if it was a mock project pertaining to the construction of a de novo assembly and downstream analyses.
